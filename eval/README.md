# eval — проверка качества без голоса

- `personas/*.md` — вымышленные рассказчики (биография по 8 блокам + манера речи + ключевые факты). Все совпадения случайны.
- `behaviors.md` — профили поведения для пограничных случаев (ключи используются в `persona_reply` и симуляторе).
- Симулятор одного персонажа (I15): `npm run sim -- --persona kim [--behavior wanders]`.
- Оценка качества по всем персонажам (I11): `npm run eval` → `reports/<дата>.md` и `reports/<дата>.json`.
- `judge.md` — промпт LLM-судьи голоса, `back_translate.md` — промпт обратного перевода KR → RU (шаги `judge`, `back_translate`).
- `judge.golden.md` — тот же шаг `judge` с `golden` (#256): какой перевод абзаца ближе по смыслу к правке носителя (`reviews/`, `golden/`).
- Отчёты пишутся в `eval/reports/` (в git не попадают).

Формат персонажа — см. `personas/kim.md`. Раздел «Ключевые факты» — эталон: симулятор сверяет с ним главы и считает потерянные или искажённые факты.

## Запуск

```
npm run eval                                        # mock: бесплатно, проверка, что всё работает
npm run eval -- --personas kim --behaviors one-word,long --questions 4
AI_MODE=gemini npm run eval -- --questions 4 --max-calls 20   # настоящий Gemini (ключ в .env.local)
npm run eval -- --compare eval/reports/2026-11-22.json --label "после правки edit.md"
```

- По умолчанию — 3 персонажа × их профили по умолчанию (`Профили по умолчанию` в карточке персонажа).
- Реальный режим: не больше `--max-calls` запросов на прогон (по умолчанию 24, из них 2 — судья и обратный перевод) и `--total-max` на весь запуск (150). Квота Gemini ~500 в сутки общая с продом.
- Темп: бесплатный Gemini режет по запросам в минуту, поэтому между настоящими вызовами пауза 6,5 с (`EVAL_MIN_INTERVAL_MS`), после 429 — 65 с и один повтор (`EVAL_RETRY_WAIT_MS`). Прогон 3 персонажей × 20 запросов — около 7 минут; из кэша — секунды.
- `--behaviors all` — только в mock.
- `--fewer-calls` (#275) — интервью в режиме «меньше вызовов» (#105 п. 1–2, у семей — флаг `lang_kk`): полнота и следующий
  вопрос одним вызовом, короткий первый ответ — уточнение по шаблону. Сравнение: два прогона, с опцией и без, `--compare`.
- `--review-set eval/reviews/sets/<имя>.json --review-pair ru-ko|ru-kk` (#232, #257) — главы прогона → набор для ссылок носителей.

## Как читать отчёт

**🎯 Цель MLP: средний голос ≥ 4 из 5.** Это главная строка отчёта.

| Метрика | Что значит | Хорошо |
| --- | --- | --- |
| Голос 1–5 | LLM-судья сравнивает главу с тем, что рассказчик сказал, и с его манерой речи: 5 — звучит как он сам, 3 — пересказ журналиста, 1 — другой человек | ≥ 4 |
| Факты потеряны / искажены | «Ключевые факты» персонажа, которых нет в главах или которые стоят с другим годом (сверка без ИИ: годы точно, слова по основе) | меньше |
| Потеряно при сборке главы | Факт прозвучал в разговоре, но пропал в главе — вина редактуры, а не интервью | 0 |
| Уточнений на вопрос | Сколько раз агент переспрашивал; 0 у «one-word» — плохо (не дособрал), 3 у «long» — тоже плохо (перебивает) | по профилю |
| KR: смысл 1–5 | Обратный перевод корейского на русский **другой моделью** и сверка с оригиналом | ≥ 4 |
| KR: флажки | Сомнительные места: 🔴 major — неверные годы, имена, родство, добавленное или пропавшее событие, кириллица в тексте; 🟡 minor — книжный тон, смешение 해요체 / 한다체 | 0 major |
| KR без ИИ (#103) | Правила `eval/kr-check.ts` по главам прогона: пояснения в скобках, которых нет в оригинале; отклонения от `docs/glossary.md` (нет эквивалента, вариант из «не:», нет пояснения при первом упоминании); смешение 해요체 / 한다체 в одном абзаце и 습니다체 | 0 |
| KR без ИИ: имена (#121) | Имя из словаря семьи прогона (люди и места с корейским написанием, как в конвейере: первая глава задаёт, правка семьи важнее) есть в русском тексте главы, а его корейского написания в главе нет — `name:spelling` | 0 |
| Время шагов | Среднее время `ai.run` по шагам (из кэша — почти 0) | edit / translate < 30 с |

- **«mock, оценка не показательна»** — ответы и главы из заглушки, судья всегда ставит 3. Mock проверяет только, что прогон и отчёт работают.
- **«обратный перевод той же моделью»** — Flash исчерпал квоту и шаг ушёл на Flash-Lite, которым и переводили: флажки менее надёжны, повторите завтра или задайте другую модель в `ai_routes`.
- Флажки KR — подсказка, где смотреть носителю (V2), а не приговор. Спорное проверяйте глазами в разделе «Корейский» полного отчёта.

## В PR

Workflow `eval` запускается на PR, где менялись `prompts/**` (или `judge.md` / `back_translate.md`): прогоняет персонажей с промптами базовой ветки («до») и с промптами PR («после») и оставляет в PR один комментарий с таблицей «до / после» (обновляет его при новых коммитах). Δ: 🟢 — лучше, 🔴 — хуже. Полный отчёт с главами — артефакт запуска и summary.

Квота: по умолчанию 3 персонажа × 4 вопроса, не больше 20 запросов на прогон; ответы кэшируются (`actions/cache`), поэтому «до» и шаги с неизменёнными промптами почти бесплатны. Вручную: Actions → eval → Run workflow (персонажи, профили, лимит; `fewer_calls`; `review_set` + `review_pair` — набор
для носителей в артефакте `eval-out/sets/<имя>.json`). Режим — `AI_MODE=gemini` (основные шаги без платного резерва);
`OPENAI_API_KEY` (#276) — только для обратного перевода kk → ru другим провайдером.

Строка **«Носители (пара)»** (#232, #256) — если в `eval/golden/` есть правки носителей: ≤ 8 свежих абзацев на пару
переводятся промптом PR, судья ИИ (один вызов на пару) сравнивает по смыслу с правкой новый перевод и тот, что правил
носитель. Хуже по смыслу или потерян факт правки (имя, год, родство) — 🔴 по фактам: не сливать. Судья недоступен — chrF.
