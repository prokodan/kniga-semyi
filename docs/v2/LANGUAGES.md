в прод переносим флагами. Успеем к финалу — Данил добавит в питч; нет — ничего страшного.
Опирается на запись «Языки (после финала)» в `docs/DECISIONS.md` (27.11) — этот документ её уточняет.

Зачем лично: прабабушке 97 лет, бабушкам и дедушкам — 80+. Их надо успеть записать, и записать хорошо:
на том языке, на котором им легко говорить, с вопросами, которые им про их жизнь, а не про чужую.

## 1. Три независимые настройки (не «режимы»)

| Настройка | Где | Значения | Кто выбирает |
|---|---|---|---|
| **Язык рассказа** | `storytellers.spoken_langs text[]` | `ru` · `kk` · `ru+kk` (смешанно) · `ru+koryo` (как сейчас) | семья при старте («на каком языке бабушке удобнее») |
| **Языки книги** | `families.book_langs text[]` (первый — основной) | `ru` · `ru,kk` · `kk,ru` · `ru,ko` (как сейчас) | семья при выборе книги |
| **Культурные пакеты** | `families.culture_packs text[]` | `general` (всегда) + слои: `kz`, `koryo`, `ua`… | семья при старте («кто вы»), можно несколько |

«Режим» для семьи — просто комбинация. Примеры:
- Прабабушка-казашка говорит по-казахски, правнуки читают по-русски → рассказ `kk`, книга `kk,ru`, пакеты `general+kz`.
- Дедушка говорит по-русски с казахскими словами → рассказ `ru+kk`, книга `ru` или `ru,kk`, пакеты `general+kz`.
- Семья Ким (демо, АКНЦ) → рассказ `ru+koryo`, книга `ru,ko`, пакеты `general+koryo` — **ровно текущее поведение**.
- Смешанная семья (папа казах, мама украинка) → пакеты `general+kz+ua`.

Язык интерфейса (`ui_locale`) — отдельно и позже; в v2 интерфейс для семьи по-русски, вопрос рассказчику — на его языке.

## 2. Культурные пакеты: общий костяк + слои

### 2.1 Принцип
- **`general`** — костяк для любого человека: 8 блоков карты жизни (ключи блоков не меняются), ~40 вопросов без
  этнических реалий («Где вы родились?», «Каким был дом?», «Как вы познакомились?»). Тексты на всех языках рассказа.
- **Слой** (`kz`, `koryo`, `ua`, …) — **патч** к костяку, не отдельный банк. Слой может:

| Операция | Пример (`kz`) |
|---|---|
| `add` — вставить вопрос после id | после `roots-04`: «Знаете ли вы свои семь колен (жеті ата)? Из какого вы рода, жуза?» |
| `reword` — переформулировать вопрос (смысл тот же) | `traditions-01`: «Какие праздники…» → «Как в вашей семье встречали Наурыз и провожали гостей?» |
| `minimum+` — дополнить минимум полноты | `roots-01`: + «род / ру, если помнит» |
| `hide` — скрыть вопрос костяка | (редко) вопрос, который в культуре неуместен |
| `glossary` — слова и реалии для расшифровки, редактуры, перевода | әже, ата, апа, аға, көке, нағашы, бесбармак, той, қымыз, ауыл |
| `kinship` — термины родства → отношения древа | нағашы ата = дедушка по маме |
| `hints` — подсказки расшифровке (имена, места) | Шымкент, Талдықорған, Сарыарқа |
| `sensitive` — трудные темы: только в `hardship`, не первыми, с разрешением не отвечать | ашаршылық 1930-х, Желтоқсан 1986 (kz); 1937 переселение (koryo); Голодомор (ua) |
| `tone` — правила обращения для вопросов и перевода | kk: всегда «Сіз», к старшим — уважительно; дети в книге — ласковые обращения допустимы |

- **Порядок слоёв** = порядок в `culture_packs`; конфликт двух `reword` одного id → берём первый слой, второй
  становится `add` после него (оба вопроса прозвучат). Это правило — тестом.
- **Текущий банк** (V0, корё-сарам) раскладывается на `general` + `koryo` без смены текстов для семей с `koryo`:
  тест «`general+koryo` = сегодняшний `QUESTIONS`» (id, порядок, ru, ko, minimum) — гарантия, что прод не меняется.

### 2.2 Где лежит
```
content/packs/
  general/questions.ts      # костяк: id, block, text: { ru, kk, ko, … }, minimum
  koryo/pack.ts             # слой: add / reword / minimum+ / hide + glossary (из docs/glossary.md), hints, sensitive, tone
  kz/pack.ts                # слой kk-культуры
  index.ts                  # resolveBank(packs, spokenLang) → Question[] — чистая функция с тестами
```
Тексты вопроса — на каждом языке рассказа (`text.kk` обязателен у каждого вопроса `general` до включения `spoken_kk`).
Тест: нет вопроса без текста для объявленного языка; id уникальны; у `add` есть существующий якорь.

### 2.3 Языковые пары (книга)
| Пара | Шаг | Промпт | Проверки без ИИ |
|---|---|---|---|
| ru → ko | `translate(ru, ko)` | `prompts/translate.ko.md` (= нынешний translate.md) | kr-check (как сейчас) |
| ru → kk | `translate(ru, kk)` | `prompts/translate.kk.md` | kk-check: буквы әіңғүұқөһ есть, нет русских слов в kk, родство по глоссарию, «Сіз», годы цифрами, имена по словарю семьи |
| kk → ru | `translate(kk, ru)` | `prompts/translate.ru.md` | ru-check: казахские слова — по глоссарию (в скобках перевод при первом упоминании), имена по словарю |
| ru+kk (смешанная речь) → ru | `edit` | `edit.md` + правило: казахские слова и фразы как сказаны, перевод в скобках при первом упоминании (как корё мар сейчас) | — |

Ключ кэша `ai_cache` включает пару языков. Глоссарии — по **культуре** (пакет), а не по языку: «апа» у казахов
и у корё-сарам — разные слова.

### 2.4 Конвейер
`uploaded → transcribing → editing → translating → ready` не меняется. Меняется, что внутри:
- **transcribe** получает `spoken_langs` и hints из пакетов. `ru+kk` — без перевода, как сказано.
- **edit** пишет главу на **основном языке книги**, если рассказ на нём; иначе — на языке рассказа, а основной получается
  переводом. Правило «оригинал = как сказано»: казахский рассказ → оригинал kk, русская версия — перевод.
- **translate** — по каждому неосновному языку книги. Тексты — в `story_texts(story_id, lang, title, text, quote, origin, status)`;
  `text_ru` / `*_ko` остаются зеркалом (миграции только добавляют, DECISIONS 27.11).
- **Книга PDF**: 1 язык — сплошной текст; 2 — разворот (как RU | KR сейчас). Шрифт: проверить казахские буквы в Noto Serif.

### 2.5 Риски (проверяем до включения флагов)
1. **Распознавание kk и ru+kk у пожилых** — главный риск. Синтетические персонажи его не проверяют (sim идёт текстом).
   Нужны 5–10 настоящих коротких записей (§5, действие Данила) → eval расшифровки: доля слов с ошибкой, имена, смешанные фразы.
2. **Озвучка вопроса на казахском**: в iOS, скорее всего, нет казахского голоса speechSynthesis → вопрос текстом + запись
   вопроса голосом носителя (mp3 в `public/`) или русский голос. Проверить на iPhone до решения.
3. **Качество kk-перевода** без носителя — закрываем ссылками для проверяющих (§3).
4. **Тексты вопросов на kk** — пишет ИИ, вычитывает носитель через ту же ссылку (режим «вопросы»).

## 3. Проверка носителем: ссылка для проверяющего (`translator_review`)

**Идея:** Данил даёт носителю личную ссылку на языковую пару. Носитель читает главы бок о бок (оригинал | перевод),
ставит оценки, правит текст прямо в абзаце и комментирует. Его правки становятся **золотым набором**: каждый следующий
PR с промптами автоматически сверяется с исправлениями людей — модель учится на носителях, а не на догадках.

### 3.1 Как это выглядит
- `/admin/reviews` (ADMIN_PIN): «Новая ссылка» → пара (`ru→kk`, `kk→ru`, `ru→ko`, или «вопросы kk»), имя проверяющего,
  набор текстов (только **вымышленные** главы eval-персонажей и демо — не главы живых семей), срок → ссылка `/review/<токен>`
  (токен хранится хэшем, как PIN).
- Проверяющий с телефона, без регистрации:
  - абзац оригинала → абзац перевода; тап по переводу — правка прямо в тексте (diff сохраняется);
  - на главу: оценка 1–5 по осям **смысл · грамматика · естественно ли звучит · обращение к старшим · имена и реалии**;
  - комментарий к абзацу или к главе; кнопка «не знаю, пропустить»;
  - внизу «Готово» — спасибо и счётчик «проверено 7 из 10».
- Режим «вопросы»: тот же экран для текстов вопросов банка на kk — носитель правит, как звучит естественно для бабушки.

### 3.2 Как правки попадают к Claude
- Таблицы: `review_links`, `review_items` (что показали: пара, текст оригинала и перевода, версия промпта / коммит),
  `review_feedback` (оценки, правки абзацев, комментарии). Миграция только добавляет, grant для service_role.
- Workflow **reviews-export** (workflow_dispatch, `target: staging|prod`): выгружает новые отзывы в
  `eval/reviews/<дата>-<пара>-<проверяющий-кратко>.md` отдельным PR — оригинал, перевод модели, правка носителя (diff),
  оценки, комментарии. Имя проверяющего — только инициалы.
- Данил пишет агенту «разбери отзывы eval/reviews/…» → агент правит `prompts/translate.<lang>.md`, глоссарий пакета,
  проверки kk-check, и добавляет пары «плохо → хорошо» в **золотой набор** `eval/golden/<пара>.jsonl`.
- **eval** на каждом PR с `prompts/**`: новый перевод золотых абзацев → судья сравнивает с правкой носителя
  (ближе / дальше, чем до PR) → строка «Носители: лучше N, хуже M» в комментарии. Хуже на фактах = 🔴.

### 3.3 Почему так
- Носителю — 10 минут с телефона, без таблиц и документов.
- Правки живут в репозитории и не теряются в чатах; каждая становится регрессионным тестом.
- Тексты живых семей проверяющим не показываем: только вымышленные персонажи и демо.

## 4. Древо семьи (`family_tree`)

- **Строится само** из словаря семьи (`family_entities` kind=person) и родства в `facts.relation` + термины родства
  пакетов (нағашы ата → дедушка по маме). Обновляется при каждой новой главе (тот же шаг, что словарь).
- **Правится на своей странице** `/f/<токен>/tree`: перетащить человека в другое поколение, «это один и тот же человек»
  (слить дубли), добавить человека, поправить имя / годы. Правка семьи (`source=family`) автоматику не перетирает — как в словаре.
- **Красиво**: поколения рядами, рассказчик в центре, супруги рядом, имена на языках книги, годы, фото (если есть).
  Тот же вид — страница в PDF книги.
- **Книга на древе**: у рассказчика — обложка «Книга Николая Петровича» → открыть. У остальных — «Записать историю
  мамы» → добавить рассказчика в семью → выбор книги. Это главный путь «вторая книга в той же семье».
- Данные: `family_relations(family_id, from_entity_id, to_entity_id, kind, source)` (kind: parent, spouse, sibling),
  у рассказчика — ссылка `storytellers.entity_id`. Поколение считаем от рёбер, не храним. Миграции только добавляют.
- Кто кому кем приходится, если рассказчиков несколько — рёбра общие, «мама» для одного = «бабушка» для внука: подписи
  считаются от того, чью книгу смотрят.
