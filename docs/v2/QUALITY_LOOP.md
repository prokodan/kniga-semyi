# Контур качества: носители и переводчики → автоматические улучшения (v2)

Статус: **дизайн 28.11, эпик — см. issue «[v2 Q] Контур качества».** Развивает §3 `docs/v2/LANGUAGES.md`
(ссылки носителей, #232) и инструменты eval (#280, #316). Цель — почти автоматический цикл:
**банк проверок → прогон боевым конвейером → проверка человеком → разбор → предложение правки → eval до/после →
одобрение → main.** Только вымышленные данные; главы живых семей — никогда.

## 1. Что проверяем: два вида материала
| Вид | Откуда | Что ловит |
| --- | --- | --- |
| **Прогон личности** | Банк личностей → боевой конвейер на staging (те же промпты, модели, маршруты): `persona_reply` отвечает на вопросы банка → расшифровка-заглушка → `edit` → `translate` на языки пары. | Сквозное качество: главы, обращения, имена, реалии в контексте целой жизни. |
| **Текст с нюансами** | Банк текстов: короткие (100–250 слов) тексты, привязанные к личности и событию, **специально нагруженные нюансами** — родство (младший / старший брат, апа, хальмони), обращение к внукам, даты и числа, советские реалии и аббревиатуры (ССР, колхоз), диалектные слова (корё мар, казахские вставки), идиомы, эмоции, имена и топонимы. Каждый текст размечен тегами нюансов. | Точечные ошибки, которые редко всплывают в прогоне: 오빠 vs 남동생, «апам» → «әжеміз», регистр сен / сіз. |

**Старт банка:** на каждую пару (`ru→ko`, `ru→kk`; позже `kk→ru`, `ru+kk` в рассказе) — **5 личностей** и
**≈ 20 текстов** (по 2–3 на каждый тег нюансов). Генерирует самая сильная доступная модель (шаг ИИ `quality_generate`,
маршрут — топовая модель OpenAI), черновик просматривает Claude продукта; дальше — кнопкой в админке.

## 2. Данные (миграции только добавляют)
- `quality_personas(id, pair, pack, name, bio, speech_style, tags[], status: new|active|archived, source: seed|generated|manual, created_at)`
- `quality_texts(id, pair, persona_id?, event, text_src, nuance_tags[], status, source, created_at)`
- `quality_runs(id, kind: persona|text, ref_id, commit_sha, prompt_versions jsonb, models jsonb, env, created_at)` —
  что именно отработало (версия промптов = хэши файлов `prompts/*`, модели из `ai_routes`).
- `quality_items(id, run_id, src_text, out_text, lang_from, lang_to, step, focus_terms jsonb)` — то, что увидит проверяющий.
- Ссылки и отзывы — существующие `review_links / review_items / review_feedback` (#232) + поля: `kind: text|terms`,
  `criteria jsonb`, `focus_terms jsonb` (оценка по словам), `item_ref → quality_items`.
- `quality_findings(id, feedback_id, pair, component: prompt|glossary|check_rule|names|model_route, severity, summary, evidence jsonb, status)`
- `quality_proposals(id, pair, findings[], branch, pr_number, eval_before jsonb, eval_after jsonb, status: draft|eval|ready|approved|rejected)`

## 3. Админка `/admin/quality` (вкладки)
1. **Банк** — личности и тексты по парам: статусы `новые → в проверке → проверены → архив`; у каждой карточки —
   «прогонов N, ссылок N, проверено N, средняя оценка». Кнопки: «+ Личность», «+ Текст» (вручную или
   «Сгенерировать N» с тегами нюансов), «В архив». Отработавшие (проверены ≥ 1 раз и нет новых находок) уходят в архив.
2. **Проверки** — «Новая ссылка»: пара → проверяющий (имя, язык интерфейса) → **что проверять**: целые тексты или
   «только выделенные слова» → выбрать материал из банка (галочки, фильтр по тегам) → срок → ссылка + QR.
   Таблица ссылок: открыта / в работе / готово, прогресс N из M, отозвать.
3. **Находки** — разбор отзывов, сгруппированный по компоненту (промпт перевода, глоссарий, правило проверки,
   словарь имён, модель): что нашли, сколько раз, примеры «было → правка носителя».
4. **Изменения** — предложения правок: PR, таблица **«было / стало»** по eval этой пары (смысл, регистр, имена,
   флажки проверок, золотой набор «ближе к правке носителя: лучше N, хуже M»), кнопки «Одобрить» (= слить PR) и
   «Отклонить» (с причиной).
5. **История** — что меняли, по каким отзывам, как изменились метрики.

## 4. Страница проверяющего `/review/<токен>` 2.0 (телефон, без регистрации)
- **Вход:** на языке проверяющего — «Что от вас нужно» (3 пункта), сколько займёт (≈ 15–20 мин), пример одной
  хорошей проверки. Кнопка «Начать».
- **Режим «текст»:** оригинал (RU) сверху / перевод снизу по абзацам; тап по абзацу перевода — правка прямо в тексте
  (diff сохраняется); 5 критериев с **якорями** (1 — смысл искажён, 3 — понятно, но неестественно, 5 — как сказал бы
  носитель): смысл · естественность · обращение и регистр · имена и реалии · грамматика; комментарий.
- **Режим «слова»:** в переводе подсвечены 3–8 фокус-слов (родство, обращения, реалии) — у каждого «верно / неверно →
  как правильно»; остальной текст можно не читать.
- «Не знаю — пропустить», автосохранение черновика, прогресс «7 из 10», в конце — спасибо и итог.
- Тексты — только вымышленные (банк), имя проверяющего в выгрузках — инициалами.

## 5. Автоматика (джобы)
1. **`quality-run`** (staging, по кнопке «Прогнать» и раз в неделю): берёт активные личности / тексты пары, гоняет
   боевой конвейер, пишет `quality_runs / quality_items`. Лимит $ на прогон (по умолчанию $2).
2. **`quality-digest`** (pg_cron раз в час + по закрытию ссылки): новые отзывы → шаг ИИ `quality_analyze` (топовая
   модель) классифицирует правки в `quality_findings` по компонентам и важности; дубли сливает.
3. **`quality-propose`** (по кнопке «Предложить правку» или авто при ≥ N находок одного компонента): агент-скрипт
   строит патч **только в разрешённых местах** — `prompts/translate.<lang>.md`, глоссарий пакета
   (`content/packs/*`), правила `eval/kk-check.ts` / `kr-check.ts`, `eval/golden/<пара>.jsonl` (правки носителя
   становятся золотыми примерами) — и открывает PR `quality/<пара>-<дата>` с описанием «какие отзывы → что меняем».
   Код конвейера и маршруты моделей — только предложением в issue, не патчем.
4. **eval на PR** (уже есть): до / после по паре + золотой набор → комментарий → `quality_proposals.eval_*` →
   вкладка «Изменения».
5. **Уведомление** в бот: «Пара ru→kk: предложение по 6 отзывам, eval: смысл 4.1 → 4.4, золотой набор лучше 5 / хуже 0 —
   [Открыть]». **Одобрение = слияние PR** (человек). Авто-слияние — позже, флагом, только если лучше везде и 0 🔴.

## 6. Границы и защита
- Только staging и вымышленные данные; ключи ИИ staging; лимиты $ на прогон и на сутки.
- Патчи — только в разрешённых файлах (проверка в `quality-propose` + CODEOWNERS-подобный тест).
- RU+KR в проде меняется только через одобренный PR с eval без ухудшений (правило волн качества сохраняется).
- Версия промптов фиксируется в каждом прогоне — всегда видно, к чему относится оценка.
