## 1. Архитектура: расти линейно, не тяжелеть
**Принцип: один Next.js + один Supabase, новые модули — папками, не сервисами.** Никаких отдельных бэкендов, очередей
и брокеров: фоновые задачи — как сейчас (`pg_cron` → `/api/cron/*`, `after()`), долгие — таблица-очередь.

| Модуль | Что | Почему так |
| --- | --- | --- |
| `lib/auth` | Supabase Auth (email OTP / magic link, Google). Сессия читается **только на сервере**; браузер по-прежнему не ходит в базу. | Ноль своей криптографии; правило «база только с сервера» сохраняется. |
| `lib/db/access.ts` | **Одна** функция доступа: `canAccess(actor, family, need)`; actor = пользователь \| гостевой токен \| киоск \| админ. Все ручки — через неё. | Права в одном месте — проще аудит, меньше дыр. |
| Схема | `profiles(user_id, ui_locale, name)`; `family_members(user_id, family_id, role: owner\|editor\|viewer)`; `orgs(id, slug, name, default_packs, default_book_langs, theme)`; `org_members(user_id, org_id, role: admin\|volunteer)`; `families.org_id` (пусто = частная семья, заменяет `source='kiosk'`); `kiosk_devices(org_id, token_hash)`. Миграции только добавляют. | Тенанты без отдельных баз; `source` остаётся для истории. |
| `lib/i18n` | Словари `content/i18n/{ru,en,kk,ko}.json`, ключи, фолбэк на `ru`, язык — cookie → профиль. Без тяжёлых библиотек (или `next-intl`, если окупится). Вычитка словарей — через `/review` (тот же контур качества). | Один источник строк; переводчики уже есть в контуре. |
| Темы | Нейтральные токены `globals.css` + `data-theme` (`neutral`, `koryo`, `kz`, …) — цвета / орнамент / подпись темы через CSS-переменные. | Корея — тема, не код. Новая диаспора = новая тема без правок страниц. |
| `lib/billing` | Каталог продуктов в коде (`catalog.ts`: книга, печать, доп. язык, сказка, вторая книга −40 %, древо), цена в $ → ₸ по курсу (460, пересчёт периодически); `orders(family_id, kind, amount, currency, provider, status)`; порт провайдера: `demo` → Kaspi / Stripe / Telegram Stars позже. | Новый платёжный блок = новый адаптер + строка каталога, экраны не трогаем. |
| Книги и обложки | `lib/book/designs/*`: 2–3 дизайна обложки и разворота — **один шаблон** для PDF, полки киоска и превью. | Не рисуем одно и то же трижды. |
| Киоск «Показ 2.0» | Полка — CSS 3D + `requestAnimationFrame`, разворот — CSS page-flip, данные — read-only эндпоинт архива (кэш 60 с), предзагрузка следующей книги. Без WebGL и тяжёлых библиотек. | iPad 60 fps, работает офлайн-кэшем при плохом Wi-Fi. |
| Лендинг | Статический (SSG), анимации — CSS scroll-driven + `IntersectionObserver`, фолбэк без анимаций (`prefers-reduced-motion`). | Быстро на 4G, без JS-тяжести. |

**Бюджеты производительности (проверяет CI / Playwright):** лендинг ≤ 150 КБ JS, LCP ≤ 2,5 с на 4G (iPhone);
страницы семьи — без роста бандла > 10 % на волну; киоск — 60 fps на iPad (Playwright trace). Расход ИИ на семью —
`/admin/ai` «Себестоимость книги» не растёт от v3 (v3 не добавляет шагов ИИ, кроме генерации текстов контура качества).

## 2. UX: простые правила для всех новых экранов
1. **Одно главное действие на экран**, остальное — ссылками. Кнопки ≥ 48 px, крупный текст, мобильный первым.
2. **Постепенное раскрытие:** язык → вход → «Создать семью» (кто ваша семья → на каком языке рассказывают → языки книги →
   рассказчик). Подсказки и плейсхолдеры — от выбранного пакета, по умолчанию — нейтральные.
3. **Точка входа решает умолчания** (#301): ссылка центра → пакет и языки центра; общая ссылка → ничего не выбрано.
4. **Пустые состояния учат:** у каждого раздела кабинета — «что это, зачем, что сделать», а не пустая таблица.
5. **Кабинет центра — панель + чек-листы:** «Сегодня в центре» (записи, книги в работе, согласия), «Как открыть киоск
   на планшете», «Как включить показ», «Отправить ссылку записавшему», «Заказать печать» — каждая инструкция в 3–5 шагов
   с картинкой.
6. **Платёжные блоки — один компонент** `OfferCard` (что входит, цена, кнопка); новый продукт = строка каталога.
