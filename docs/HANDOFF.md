## 1. Продукт за 1 минуту
«Книга семьи / 우리 이야기»: семья записывает голос старшего → ИИ (без живого редактора) делает главы RU | KR →
книга PDF A5 с QR-кодами на настоящий голос. Бесплатная первая глава → покупка книги (цифра / печать) → допы
(сказка для внуков и др.). B2B: АКНЦ «90 историй к 90-летию» — киоск на планшете + кабинет центра + архив.
Полная продуктовая логика — `docs/PRODUCT_LOGIC.md`. Короткая — `docs/PRODUCT.md`. Архитектура — `docs/ARCHITECTURE.md`.

Конкурс Startup-Nunchi (АКНЦ): **полуфинал пт 27.11.2026**, финал 6.12.2026, питч 5 минут.
**Заморозка фич — ср 25.11 14:00.** После неё — только багфиксы и полировка; новое — в ветках до 27.11.

Команда: **Данил** — продакт, владелец репозитория и инфраструктуры (GitHub, Vercel, Supabase, ключи).
**Влад** — аналитик, носитель корейского, контрибьютор: ручные проверки, корейский, багфиксы через своего Claude/Codex.

## 3. Как работаем (обязательно для каждого агента)
1. **Одна задача = один новый чат агента = одна ветка = PR.** Задачи — GitHub Issues. Длинные чаты сжигают лимиты.
2. Начало: `AGENTS.md` → своя issue → `docs/STATUS.md`. Больше заранее ничего не читать.
3. PR по шаблону. **Раздел «📝 Заметки для команды» обязателен** (см. п. 4).
4. **Всё, что агент хотел бы сказать человеку, пишется в репозиторий, а не только в чат:**
   - в PR → «📝 Заметки для команды»: на что обратить внимание, принятые решения, что не сделано и почему,
     что проверить руками с телефона (точные ссылки);
   - каждое «осталось / потом / нужно руками» → **сразу отдельная issue** (метки зоны; без milestone, если после
     питча) и ссылка на неё в заметках;
   - решение, влияющее на других, → строка в `docs/DECISIONS.md`.
   Финальное сообщение агента в чате = копия заметок из PR. Так любой (человек или Claude) видит всё по PR/issues,
   ничего не собирается вручную из чатов.
5. Слияние: агент **сам** сливает свой PR (squash), но только когда зелёные `ci` **и** `e2e`; если PR меняет
   `prompts/` — ещё дождаться комментария `eval` (🔴 по фактам = не сливать). Слияние при красной проверке запрещено.
6. После слияния: если были миграции — дождаться `migrate`; затем `smoke`; если трогал демо — `seed-demo`.
7. Конфликт с main → влить main в ветку и разрешить; конфликт в `docs/STATUS.md` → оставить строки обеих зон.
8. Ключи, `LISTEN_SECRET`, данные демо-семьи — не трогать без явного разрешения Данила.
9. В среде агента нет ключей ИИ и доступа к базе: живые прогоны — через workflows (`sim`, `eval`, `diag`, `ai-models`,
   `smoke`, `seed-demo`) по `workflow_dispatch`; GitHub API — только REST (GraphQL недоступен).
